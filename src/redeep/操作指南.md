# MultiHop-RAG 迁移与运行操作指南

这份文档面向把整个 `multihop-rag` 目录迁移到新机器后，第一次接手项目的用户或 AI。
所有命令默认在项目根目录执行，也就是包含 `src/`、`configs/` 和 `requirements.txt`
的目录。

## 1. 项目当前完成的内容

当前项目不是原始单跳 ReDeEP 的直接复制，而是以下完整流程：

```text
HotpotQA / 2WikiMultiHopQA / MuSiQue
        |
        v
FlashRAG 固定 hop 多跳检索
        |
        v
Qwen2.5-7B-Instruct 生成最终答案，并保存每一跳 trace
        |
        v
答案 token-F1 弱标签：F1 <= 0.30 为幻觉
        |
        v
Qwen ReDeEP：ECS + PKS -> train 校准 -> dev 检测
```

主要代码位置：

- `src/fixed_hop_pipeline.py`：固定 hop 的多跳检索、query 改写和答案生成。
- `src/hallucination_labels.py`：三个数据集共用的答案 F1 弱标签和检索充分性判断。
- `src/redeep/qwen_extractor.py`：Qwen attention、FFN residual 和 Logit Lens 状态提取。
- `src/redeep/scores.py`：token-level ECS 和 PKS。
- `src/redeep/chunk_scores.py`：chunk-level ECS/PKS 聚合。
- `src/redeep/calibration.py`：train 上选择 heads/layers、归一化范围、`alpha` 和阈值。
- `src/redeep/detector.py`：端到端 ReDeEP 检测。
- `src/run_redeep.py`：`fit` 和 `evaluate` 命令行入口。
- `configs/flashrag_fixed_hop.yaml`：多跳检索和答案生成配置。
- `configs/redeep.yaml`：Qwen ReDeEP 配置。

当前明确不做的内容：

- 不使用原始 ReDeEP 的 LLaMA2-7B；当前使用 `Qwen/Qwen2.5-7B-Instruct`。
- 不实现 AARF 干预。
- 不把 ECS-only、PKS-only 作为对照结果；最终使用完整联合分数：

```text
ReDeEP = normalized_PKS - alpha * normalized_ECS
```

原始 `ReDEeP-ICLR/` 目录只是论文代码参考，当前适配代码在 `src/redeep/`。

## 2. 迁移后先检查目录

如果是直接复制整个目录，先进入项目根目录：

```bash
cd /path/to/multihop-rag

ls
```

应该至少看到：

```text

requirements.txt
configs/
src/
tests/
```

数据、Wikipedia 语料和 BM25 索引被 `.gitignore` 忽略，不会随 Git 提交同步。如果是从
GitHub 重新 clone，而不是完整复制目录，需要另外复制下面的本地数据：

```text
data/FlashRAG_Data/hotpotqa/train.jsonl
data/FlashRAG_Data/hotpotqa/dev.jsonl
data/FlashRAG_Data/2wikimultihopqa/train.jsonl
data/FlashRAG_Data/2wikimultihopqa/dev.jsonl
```

```bash
find data/FlashRAG_Data -maxdepth 2 -type f -name '*.jsonl' | sort
ls -lh data/wiki_corpus.jsonl
ls -ld data/index/bm25
```

如果 `data/wiki_corpus.jsonl` 或 `data/index/bm25` 不存在，后面的多跳检索不能运行。

## 3. 创建 Python 虚拟环境

建议使用 Python 3.10 或 3.11。不要直接污染系统 Python：

```bash
cd /path/to/multihop-rag
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
```

之后每次重新打开终端都要先激活：

```bash
cd /path/to/multihop-rag
source .venv/bin/activate
```

Windows PowerShell 对应命令：

```powershell
cd C:\path\to\multihop-rag
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip setuptools wheel
```

## 4. 安装 GPU 运行环境

先确认 NVIDIA 驱动和 GPU：

```bash
nvidia-smi
```

PyTorch 的 CUDA wheel 要和机器驱动兼容。下面只是示例，具体 CUDA 版本应以 PyTorch
官网给出的安装命令为准。以 CUDA 12.1 wheel 为例：

```bash
python -m pip install torch torchvision torchaudio \
  --index-url https://download.pytorch.org/whl/cu121
```

如果机器适合 CUDA 12.4，就把 `cu121` 换成 `cu124`；不要在同一个虚拟环境中混装多个
CUDA wheel。然后安装项目依赖：

```bash
python -m pip install -r requirements.txt
```

验证 Python、PyTorch 和 CUDA：

```bash
python - <<'PY'
import torch

print("torch:", torch.__version__)
print("cuda available:", torch.cuda.is_available())
print("cuda version:", torch.version.cuda)
if torch.cuda.is_available():
    print("gpu count:", torch.cuda.device_count())
    print("gpu 0:", torch.cuda.get_device_name(0))
PY
```

必须看到 `cuda available: True` 才适合运行 Qwen ReDeEP。若为 `False`，先不要运行完整
实验；否则模型可能落到 CPU，表现为显存和利用率异常、速度极慢。

FlashRAG 使用固定 commit，依赖安装失败时先确认机器有 Git 和网络：

```bash
git --version
python -m pip show flashrag transformers accelerate
```

## 5. 下载或确认 Qwen 模型

代码默认模型为：

```text
Qwen/Qwen2.5-7B-Instruct
```

第一次运行会从 Hugging Face 下载模型，建议把缓存放在容量足够的磁盘：

```bash
export HF_HOME="$PWD/.cache/huggingface"
mkdir -p "$HF_HOME"
```

如果所在网络需要 Hugging Face 登录：

```bash
python -m pip install -U huggingface_hub
huggingface-cli login
```

可以先单独测试 tokenizer 和模型是否可访问：

```bash
python - <<'PY'
from transformers import AutoTokenizer

name = "Qwen/Qwen2.5-7B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(name, trust_remote_code=True)
print("tokenizer loaded:", name)
print("vocab size:", len(tokenizer))
PY
```

模型需要较大的 GPU 显存。`device_map: auto` 会自动切分模型；如果有多张 GPU，先用
`nvidia-smi` 确认进程实际使用的是哪张卡。

## 6. 准备 BM25 检索索引

配置要求：

```text
corpus_path: data/wiki_corpus.jsonl
index_path:  data/index/bm25
bm25_backend: bm25s
```

如果索引还不存在，在项目根目录运行：

```bash
python -m flashrag.retriever.index_builder \
  --retrieval_method bm25 \
  --corpus_path data/wiki_corpus.jsonl \
  --bm25_backend bm25s \
  --save_dir data/index
```

FlashRAG 会在 `data/index` 下生成 `bm25/`。检查：

```bash
find data/index/bm25 -maxdepth 2 -type f | sort | head
```

建立 BM25 索引主要是 CPU 和磁盘工作，GPU 利用率为 0 在这个阶段是正常现象。

## 7. 先做代码和小规模冒烟检查

不加载 Qwen 的静态检查：

```bash
python -B -m unittest discover -s tests -v
python -m pyflakes src tests
python -m flake8 src tests --max-line-length=120 --extend-ignore=E203
python -B -m src.run_redeep fit --help
python -B -m src.run_redeep evaluate --help
```

如果新环境没有 `pyflakes` 或 `flake8`，先安装：

```bash
python -m pip install pyflakes flake8 black
```

建议先只运行一个数据集、一个 split 的少量样本。当前 `src/run.py` 使用 FlashRAG 原生
数据读取，最稳妥的做法是临时复制配置并使用只包含少量 JSONL 记录的临时数据目录。
不要第一次直接跑 HotpotQA 全部 90,447 条 train。

复制配置：

```bash
cp configs/flashrag_fixed_hop.yaml configs/flashrag_smoke.yaml
```

然后把 `configs/flashrag_smoke.yaml` 中的数据集和 split 改成目标测试集。若要严格限制
样本数，建议创建只包含前 N 行的临时 JSONL：

```bash
mkdir -p data/FlashRAG_Data/smoke
head -n 8 data/FlashRAG_Data/hotpotqa/dev.jsonl > data/FlashRAG_Data/smoke/dev.jsonl
```

再将 smoke 配置中的 `dataset_name` 改为 `smoke`。这样不会修改原始数据集。

## 8. 生成多跳 RAG trace

先生成 train。ReDeEP 的 train calibration 必须来自已经完成检索和答案生成的输出：

```bash
PYTHONPATH=. python -u -m src.run \
  --config configs/flashrag_fixed_hop.yaml \
  --dataset_name hotpotqa \
  --split train
```

再生成 dev：

```bash
PYTHONPATH=. python -u -m src.run \
  --config configs/flashrag_fixed_hop.yaml \
  --dataset_name hotpotqa \
  --split dev
```

另外两个数据集只需替换名称：

```bash
PYTHONPATH=. python -u -m src.run --config configs/flashrag_fixed_hop.yaml --dataset_name 2wikimultihopqa --split train
PYTHONPATH=. python -u -m src.run --config configs/flashrag_fixed_hop.yaml --dataset_name 2wikimultihopqa --split dev
PYTHONPATH=. python -u -m src.run --config configs/flashrag_fixed_hop.yaml --dataset_name musique --split train
PYTHONPATH=. python -u -m src.run --config configs/flashrag_fixed_hop.yaml --dataset_name musique --split dev
```

FlashRAG 的 `save_dir` 会根据配置和数据集生成实际输出目录。不要假设文件一定在固定
目录，运行后查找：

```bash
find outputs -type f -name '*fixed_hop.json' -print
```

有效的 pipeline 输出必须包含 `fixed_hop_trace`、`answer_prompt`、`prompt_parts`、
`response_token_ids` 和 `redeep_records`。原始下载的 `train.jsonl` 不包含这些字段，不能
直接交给 `src/run_redeep.py`。

## 9. 运行 ReDeEP：先 fit，再 evaluate

下面以 HotpotQA 为例。先用 train 做校准。由于 FlashRAG 的 `save_dir` 可能包含数据集
子目录，先自动定位生成文件：

```bash
TRAIN_TRACE="$(find outputs -type f -name 'hotpotqa_train_fixed_hop.json' -print -quit)"
DEV_TRACE="$(find outputs -type f -name 'hotpotqa_dev_fixed_hop.json' -print -quit)"
test -n "$TRAIN_TRACE" || { echo "train trace not found"; exit 1; }
test -n "$DEV_TRACE" || { echo "dev trace not found"; exit 1; }
echo "train: $TRAIN_TRACE"
echo "dev:   $DEV_TRACE"
```

先用 train 做校准：

```bash
PYTHONPATH=. python -u -m src.run_redeep fit \
  --config configs/redeep.yaml \
  --input "$TRAIN_TRACE" \
  --output outputs/redeep_hotpotqa_train.jsonl \
  --calibration outputs/redeep_hotpotqa.calibration.json \
  --max-records 500 \
  --no-token-scores
```

`--max-records 500` 只适合第一次冒烟或快速校准测试。正式结果要去掉它；样本必须同时
包含标签 0 和 1，否则 calibration 会停止并提示扩大样本数。

再用同一份 train calibration 评估 dev：

```bash
PYTHONPATH=. python -u -m src.run_redeep evaluate \
  --config configs/redeep.yaml \
  --input "$DEV_TRACE" \
  --output outputs/redeep_hotpotqa_dev.jsonl \
  --calibration outputs/redeep_hotpotqa.calibration.json \
  --no-token-scores
```

注意：如果 fit 使用了 `--max-records 500`，这只限制 train 校准输入，不应该在正式 dev
评估时使用同一个参数。三个数据集建议各自使用自己的 train calibration：

```text
hotpotqa_train -> hotpotqa calibration -> hotpotqa dev
2wiki_train    -> 2wiki calibration    -> 2wiki dev
musique_train  -> musique calibration  -> musique dev
```

`--label-mode f1_answer` 是默认设置。如果要把未检索到支持文档的样本排除在校准和指标外：

```bash
--label-mode f1_retrieval_aware
```

## 10. GPU 利用率为 0、显存占用约 80% 时怎么判断

先不要只根据一个瞬时的 `GPU-Util: 0%` 判断程序死了。可能情况包括：

1. Qwen 已经加载到显存，但当前进程在 CPU 分词、BM25 检索、JSON 写盘或等待下一条样本。
2. 多张卡时，模型只放在其中一张卡，观察了没有任务的那张卡。
3. CUDA allocator 已经保留显存，但当前没有 active kernel；显存占用不等于 GPU 正在计算。
4. 模型实际加载到了 CPU，GPU 只保留了部分权重或缓存。
5. 程序在等待网络下载模型、磁盘读取、NFS 文件或进程锁。
6. CUDA/PyTorch 安装不匹配，导致模型没有真正执行 GPU forward。

持续观察 GPU，而不是只看一次：

```bash
watch -n 1 nvidia-smi
```

另一个终端查看 Python 进程：

```bash
ps -ef | grep -E 'src.run|src.run_redeep|python' | grep -v grep
```

确认 PyTorch 是否能执行 GPU 计算：

```bash
python - <<'PY'
import time
import torch

assert torch.cuda.is_available(), "CUDA is not available"
device = torch.device("cuda:0")
x = torch.randn((4096, 4096), device=device)
y = torch.randn((4096, 4096), device=device)
torch.cuda.synchronize()
start = time.time()
z = x @ y
torch.cuda.synchronize()
print("GPU matmul seconds:", round(time.time() - start, 3))
print("allocated GB:", round(torch.cuda.memory_allocated() / 1024**3, 2))
print("reserved GB:", round(torch.cuda.memory_reserved() / 1024**3, 2))
PY
```

判断方法：

- 这个矩阵乘法明显使用 GPU，但 ReDeEP 进程长时间 0%：优先检查当前进程是否在 CPU
  检索、分词、读写文件或等待；查看终端最后一条日志和输出文件大小是否持续变化。
- `torch.cuda.is_available()` 为 `False`：先修复 CUDA 版 PyTorch，不要调模型参数。
- GPU 显存一直增长但日志没有新样本：可能是第一次加载模型、模型下载、显存不足前的
  分配，或进程卡在某个 batch；查看 `dmesg`、Python traceback 和系统内存。
- 多卡只有一张卡显存高：`device_map=auto` 可能把模型集中放在一张卡，这是正常的；
  不要只观察空闲卡。
- 运行 BM25 索引构建或检索阶段 GPU 为 0：这是正常的，因为 BM25s 主要使用 CPU。

为了让日志及时显示，运行命令使用 `python -u`。为了先降低显存和定位问题，可以：

```bash
CUDA_VISIBLE_DEVICES=0 PYTHONPATH=. python -u -m src.run_redeep evaluate \
  --config configs/redeep.yaml \
  --input outputs/hotpotqa_dev_fixed_hop.json \
  --output outputs/debug_redeep.jsonl \
  --calibration outputs/hotpotqa_redeep.calibration.json \
  --max-records 1 \
  --max-input-tokens 2048 \
  --no-token-scores
```

如果单卡运行，需要把 `configs/redeep.yaml` 的 `device_map` 改为 `none`，并设置：

```yaml
device: "cuda:0"
device_map: "none"
```

修改 `max_input_tokens` 或 `generator_max_input_len` 后，应重新生成对应的 pipeline 输出；
不要拿使用旧 prompt 生成的答案和新 prompt 混合检测。

## 11. 常见错误

### `Corpus not found`

准备 `data/wiki_corpus.jsonl`，并确认当前工作目录是项目根目录：

```bash
pwd
ls -lh data/wiki_corpus.jsonl
```

### `BM25 index not found`

重新建立索引：

```bash
python -m flashrag.retriever.index_builder \
  --retrieval_method bm25 \
  --corpus_path data/wiki_corpus.jsonl \
  --bm25_backend bm25s \
  --save_dir data/index
```

### `CUDA is not available`

确认进入了正确虚拟环境、安装的是 CUDA 版 PyTorch、驱动可见且没有设置错误的
`CUDA_VISIBLE_DEVICES`：

```bash
which python
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.version.cuda)"
nvidia-smi
```

### `fit requires both label classes`

当前 train 子集只有一个标签类别。扩大 `--max-records`，或检查答案生成是否全部为空/全部
正确。正式 calibration 不能只使用单一标签。

### `Calibration/runtime mismatch`

evaluate 使用的模型、粒度、embedding、标签模式或 F1 阈值和 fit 不一致。使用同一份
`configs/redeep.yaml` 和同一份 calibration；三个数据集不要混用 calibration。

### `saved prompt plus response exceeds max_input_tokens`

该样本不会被静默截断，而是输出 `redeep_score: null`。降低生成配置的
`generator_max_input_len` 后重新生成 trace，或合理提高 ReDeEP 的 `--max-input-tokens`。

## 12. 给下一位 AI 的交接信息

接手后先阅读：

```text
README.md
src/redeep/README.md
src/redeep/操作指南.md
configs/flashrag_fixed_hop.yaml
configs/redeep.yaml
src/run.py
src/run_redeep.py
```

当前研究约束：

- 研究目标是多跳 RAG 下的 hallucination detection，不是普通答案准确率优化。
- 主要 baseline 是完整 ReDeEP ECS + PKS 联合方法。
- 模型使用 Qwen，不切回原始 LLaMA2-7B。
- 不加入 AARF，不做 ECS-only/PKS-only 对照组。
- 三个数据集共用 `answer_f1 <= 0.30` 的幻觉弱标签规则。
- train 用于 calibration，dev 只做固定参数评估。
- 当前代码已完成静态检查和无模型单元测试，但新环境仍需完成真实 GPU/Qwen/BM25 端到端验证。

不要直接修改原始 `ReDEeP-ICLR/` 参考实现；如果需要改实验逻辑，修改 `src/redeep/`、
`src/run_redeep.py`、配置或测试，并记录模型、数据集、split、label mode、F1 阈值和
calibration 文件。
