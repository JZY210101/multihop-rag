# 原始数据与 B 方式运行指南

当前入口使用原始完整支持段落、B 方式累积输入与共享 EM/F1/yes-no 标签。部署目录为 AutoDL 的 `/root/autodl-tmp/multihop-rag`，环境为 `multihop-rag`。应以相同 Git 提交与数据校验结果确认本地、GitHub 和 AutoDL 的版本一致。

## 数据与执行方式

`data/raw/` 保存 ModelScope 原始数据，`data/processed/` 是新运行入口的输入。三个数据集均保留全量，共六个文件，总计 300,237 条：

| 数据集 | train | dev |
|---|---:|---:|
| HotpotQA | 90,447 | 7,405 |
| 2WikiMultiHopQA | 167,454 | 12,576 |
| MuSiQue-Ans | 19,938 | 2,417 |

仅选择正确支持段落，保留完整文本。MuSiQue 使用官方分解顺序；HotpotQA、2Wiki 使用支持事实标题首次出现的顺序。

与旧 FlashRAG 重合的样本已逐条核对顺序。2Wiki train 的参考只有前 15,000 条，其余 152,454 条采用相同排序规则。支持标题顺序是固定输入约定，不代表官方推理链。

此前排除的 2Wiki dev 样本已恢复，当前 processed 不排除任何样本。原始 train/dev 数量及不同跳数／输入步数统计见 `data/raw/README.md`。

```text
问题 + D1                   -> R1
问题 + D1、D2 + R1          -> R2
问题 + D1、D2、D3 + R1、R2  -> 最终答案
```

原始子问题、标准中间答案仅用于选段落、排序和离线核查，不输入模型。每步的 `prompt_parts.context` 对应全部已出现支持段落；历史模型响应放在 prefix 中，不充当原始证据。

`num_steps` 是执行次数。新 trace 的兼容字段 `hop_num` 也表示执行次数；MuSiQue 另有原始 `dataset_hop_count`，HotpotQA、2Wiki 此字段为 null，因为原始文件没有逐样本显式跳数。

```bash

  --train-records 64 --max-train-records 256 --dev-records 16 \

```

默认使用 seed 42 随机抽样。train 缺少标签类别时，自动扩大到 128/256 条，不修改或伪造标签。
输出目录默认带时间戳；`--output-dir` 可指定一个尚不存在的目录。详细日志在该目录的 `logs/`。
若出现 CUDA OOM，使用新输出目录并将 `--score-batch-size` 降为 1。

新生成入口默认拒绝覆盖已有输出；重新生成相同文件需显式添加 `--overwrite`。尚未实现断点续跑。

## 生成结果检查

```bash
python - <<'PY'
import json
from pathlib import Path
for dataset in ('hotpotqa', '2wikimultihopqa', 'musique'):
    path = Path('outputs/original_b/smoke') / f'{dataset}_dev_oracle.jsonl'
    assert path.is_file(), f'缺少生成结果：{path}'
    rows = [json.loads(line) for line in path.open() if line.strip()]
    assert len(rows) == 5, (path, len(rows))
    for row in rows:
        assert row['history_mode'] == 'cumulative_evidence_and_responses'
        assert row['evidence_complete']
        assert len(row['hop_records']) == row['num_steps']
        for step, hop in enumerate(row['hop_records'], 1):
            assert len(hop['visible_doc_ids']) == step
            assert hop['prompt_parts']['prompt'] == (
                hop['prompt_parts']['prefix'] + hop['prompt_parts']['context'] + hop['prompt_parts']['suffix']
            )
    print(path, 'OK', len(rows))
PY
```

## 后续 ReDeEP 实验

确认真实生成正常后，生成新 train/dev trace，再重新 fit/evaluate。输入提示词、证据和样本范围已改变，旧校准文件与旧结果继续留档，新校准使用独立路径。ECS/PKS 数学不变；答案标签采用 [共享 EM/F1/yes-no 规则](../../data/ANSWER_LABELS.md)，F1 通过条件为大于等于 0.3。若仅更新标签，可复用同一批原始生成 trace，重新 fit/evaluate。

正式实验统一使用上述固定输入顺序和原始全量数据。已按旧排序生成的 trace 需要重新生成，避免复用旧校准文件。

以下命令是完整数据集的正式运行示例；不带 `--max-records`，会处理全部样本。
请先完成小规模检查，并给本次实验使用一个新的输出目录。32GB GPU 的 fit/evaluate 从 batch 1 开始；
完整证据较长时，显存需求显著高于小样本，不以 smoke 的 batch 大小保证全量可运行。

```bash
cd /root/autodl-tmp/multihop-rag
source /root/miniconda3/etc/profile.d/conda.sh
conda activate multihop-rag
export PYTHONPATH=.
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
export TOKENIZERS_PARALLELISM=false
set -euo pipefail

run_dir=outputs/original_b/full_emf1_v2
mkdir -p "$run_dir/logs"
for dataset in hotpotqa 2wikimultihopqa musique; do
  for split in train dev; do
    python -m src.run_oracle \
      --input "data/processed/$dataset/$split.jsonl" \
      --dataset "$dataset" --model model/Qwen3-4B-Instruct-2507 \
      --batch-size 4 --progress-every 100 --f1-threshold 0.30 \
      --output "$run_dir/${dataset}_${split}_oracle.jsonl" \
      2>&1 | tee "$run_dir/logs/${dataset}_${split}_oracle.log"
  done

  python -m src.run_redeep fit \
    --config configs/redeep.yaml \
    --input "$run_dir/${dataset}_train_oracle.jsonl" \
    --output "$run_dir/${dataset}_train_redeep.jsonl" \
    --calibration "$run_dir/${dataset}.calibration.json" \
    --batch-size 1 --progress-every 100 --no-token-scores \
    2>&1 | tee "$run_dir/logs/${dataset}_fit.log"

  python -m src.run_redeep evaluate \
    --config configs/redeep.yaml \
    --input "$run_dir/${dataset}_dev_oracle.jsonl" \
    --output "$run_dir/${dataset}_dev_redeep.jsonl" \
    --calibration "$run_dir/${dataset}.calibration.json" \
    --batch-size 1 --progress-every 100 --no-token-scores \
    2>&1 | tee "$run_dir/logs/${dataset}_evaluate.log"
done
```

evaluate 日志末尾的 `metrics` 包含 ROC-AUC、AUPRC（average precision）、检测 F1、precision、recall、PCC；
`answer_em`/`answer_f1` 用于构造真实弱标签，不能与检测器分类 F1 混淆。
超长完整证据默认报错，正式实验不添加 `--allow-evidence-truncation` 来静默改变证据范围。
